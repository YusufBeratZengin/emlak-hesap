# Security policy

Security fixes target the latest released version. Upgrade before reporting a suspected issue and include the affected version in your report.

## Private vulnerability reporting

Use [GitHub's private vulnerability reporting form](https://github.com/YusufBeratZengin/emlak-hesap/security/advisories/new). The maintainer must enable private vulnerability reporting in repository settings. If the form is unavailable, request a private reporting channel through a public issue containing no vulnerability details, exploit, logs or personal data. Wait for that channel before sharing details.

Describe impact, reproduction steps using fictional inputs, affected versions and a possible mitigation. Never include credentials, customer information, property records or financial data. Do not report vulnerabilities in public issues or pull requests. Reports are triaged privately; a coordinated advisory can be published after a fix is available. No response-time guarantee is made.

Calculation disagreements without a security impact belong in the [bug report form](https://github.com/YusufBeratZengin/emlak-hesap/issues/new?template=bug_report.yml). This software is not legal, tax or financial advice.
